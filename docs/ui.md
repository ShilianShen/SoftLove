# UI 设计理念

## 职责边界

UI 的职责是渲染。它根据数据和控制器状态决定显示什么，以及如何显示。

控制器包括鼠标、键盘等输入来源。UI 可以根据鼠标位置、按键状态等改变渲染内容，例如显示悬停效果、按下效果或不同的内容区域。因此，“只负责渲染”不意味着 UI 只能绘制静态画面，也不意味着 UI 必须无状态。

UI 可以向使用者提供调用 API 所需的信息，但不负责调用该 API。由使用者决定是否调用、何时调用，以及如何处理调用结果。这里的使用者指接入 UI 的应用代码。

例如，UI 可以根据鼠标位置渲染某个条目的悬停效果，并向应用提供当前指向的条目标识。应用结合控制器状态决定是否调用“选择条目”的 API，再将更新后的数据交给 UI 渲染。

## Widget 数据

Widget 的位置和尺寸保存在 `bounds = { x = 0, y = 0, w = 0, h = 0 }` 中，`z` 保留在 widget 顶层。声明可只指定部分 `bounds` 字段，其余字段按类型继承并最终补零。子组件的 `_layout(self, bounds)` 收到父组件的 `bounds`；根组件仍接收窗口的边界数据。每个实例的 `bounds` 独立保存，布局时不会与父组件或窗口共用同一个表。

公开视图继续只暴露标量，`bounds` 与其他表属性一样不会通过 `get` 暴露。

Widget 使用两个独立的表保存数据，默认均为空表：

- `userData`：用户给出的输入，例如原始文本、字体、布局参数和业务数据。
- `loveData`：为了绘制而产生的数据，例如格式化后的显示文本、选中样式和根据输入计算出的显示参数。

修改输入的方法直接放在 `userData` 中，使用 `widget.userData:method(...)` 调用，其中 `self` 是 `userData`。Widget 不再提供独立的 `setter` 字段。应用负责命中检测，再调用对应的数据方法。

组件根据 `userData` 生成 `loveData`，绘制时使用相应数据。生成显示结果时应将结果写入 `loveData`，保留 `userData` 中的原始输入。原来的 `state` 字段已移除，调用方需要按用途迁移到这两个字段。

`_draw` 的签名为 `function(userData, loveData, bounds, themes)`，由 `Widget:draw` 按这个顺序传入当前 widget 的数据、边界及主题，不再传入 widget 本身。

`_update` 的签名为 `function(userData, loveData, params, children)`，由 `Widget:update` 按这个顺序传入当前 widget 的输入、绘制数据、更新参数及子组件数据映射。这里的 `children[key]` 是对应子组件的 `userData`，保留原来的键，直接使用 `children.label.text` 或 `children.label:method(...)`。映射表每次调用重新构建，其中的数据表引用与子组件共享；替换映射项不会替换实际子组件。

`_update` 可以生成 `loveData`，也可以给子组件传递输入，但不再接收 widget 对象。组件的 `active` 等顶层属性由应用管理；示例在更新前的 `prepare` 任务中设置详情面板的启用状态。

## 渲染反馈与动作执行

- **渲染反馈**：根据控制器状态改变颜色、边框、提示或显示区域，属于 UI 的职责。
- **提供信息**：暴露命中对象、条目标识、坐标等调用 API 所需的信息，属于 UI 可以提供的能力。
- **动作执行**：根据这些信息调用 API，由应用负责，不由 UI 代为执行。

设计交互能力时，应保持这个边界，不能因为 UI 能识别鼠标指向的对象，就让 UI 自动执行该对象对应的动作。

## 裁剪与滚动的含义

裁剪是限制内容的可见范围：子组件超出指定窗口的部分不显示。它改变的是绘制范围，不要求改变内容本身的尺寸。

滚动是在可见窗口内展示内容的不同部分，通常由内容平移和裁剪共同实现。例如，窗口高 200 像素，内容高 600 像素：滚动偏移为 0 时显示内容的 0～200，偏移为 100 时显示 100～300。

这两种能力可以遵循上述职责边界：UI 根据数据或控制器状态渲染相应区域，并提供应用所需的信息；涉及 API 调用的动作仍由应用执行。这里不限定滚动偏移必须由哪一层保存，也不表示已经确定具体的容器接口或实现方案。
